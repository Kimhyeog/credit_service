# Soft Delete란? — isAvailable 필드의 의미

> Phase 2 Step 2-1 Menu 모델의 `isAvailable` 관련 설명

---

## 한 줄 요약

데이터를 **실제로 삭제(DELETE)**하지 않고, **"비활성" 표시만 해서 숨기는 것**이 soft delete다.

---

## 상황 예시

카페 POS 시스템에서 "딸기스무디" 메뉴가 있다고 하자.

### 1단계: 정상 운영 중

```
Menu 테이블:
┌─────┬──────────────┬───────┬─────────────┐
│ id  │ name         │ price │ isAvailable │
├─────┼──────────────┼───────┼─────────────┤
│ m1  │ 아메리카노    │ 4500  │ true        │
│ m2  │ 딸기스무디    │ 6000  │ true        │
└─────┴──────────────┴───────┴─────────────┘

Order 테이블:
┌─────┬─────────┬─────────────┐
│ id  │ status  │ totalAmount │
├─────┼─────────┼─────────────┤
│ o1  │ PAID    │ 6000        │
└─────┴─────────┴─────────────┘

OrderItem 테이블:
┌─────┬─────────┬────────┬───────┐
│ id  │ orderId │ menuId │ price │
├─────┼─────────┼────────┼───────┤
│ i1  │ o1      │ m2     │ 6000  │  ← "딸기스무디 주문 이력"
└─────┴─────────┴────────┴───────┘
```

고객이 딸기스무디를 주문했고, 결제도 완료됐다. OrderItem이 `menuId: m2`를 참조하고 있다.

---

### 2단계: 딸기스무디를 메뉴에서 빼고 싶다

여름이 끝나서 딸기스무디를 더 이상 판매하지 않으려 한다.

---

#### 방법 A: 물리 삭제 (Hard Delete) — 실제로 DELETE

```sql
DELETE FROM Menu WHERE id = 'm2';
```

```
Menu 테이블:
┌─────┬──────────────┬───────┬─────────────┐
│ id  │ name         │ price │ isAvailable │
├─────┼──────────────┼───────┼─────────────┤
│ m1  │ 아메리카노    │ 4500  │ true        │
│     │              │       │             │  ← m2 사라짐!
└─────┴──────────────┴───────┴─────────────┘

OrderItem 테이블:
┌─────┬─────────┬────────┬───────┐
│ id  │ orderId │ menuId │ price │
├─────┼─────────┼────────┼───────┤
│ i1  │ o1      │ m2     │ 6000  │  ← m2를 참조하는데... m2가 없다!
└─────┴─────────┴────────┴───────┘
```

**문제 발생:**

```
관리자가 주문 o1 상세를 조회하면:

  주문 #1
  ├─ 메뉴: ???           ← menuId "m2"에 해당하는 Menu가 없음
  ├─ 가격: 6,000원
  └─ 상태: 결제완료

  → 에러 발생 또는 "알 수 없는 메뉴" 표시
  → DB에 따라 외래키 제약 위반으로 DELETE 자체가 실패할 수도 있음
```

과거 주문 이력이 깨진다. 이미 결제된 주문인데 "뭘 주문했는지" 알 수 없게 된다.

---

#### 방법 B: Soft Delete — isAvailable = false로 변경

```sql
UPDATE Menu SET isAvailable = false WHERE id = 'm2';
```

```
Menu 테이블:
┌─────┬──────────────┬───────┬─────────────┐
│ id  │ name         │ price │ isAvailable │
├─────┼──────────────┼───────┼─────────────┤
│ m1  │ 아메리카노    │ 4500  │ true        │
│ m2  │ 딸기스무디    │ 6000  │ false       │  ← 데이터는 살아있음!
└─────┴──────────────┴───────┴─────────────┘

OrderItem 테이블:
┌─────┬─────────┬────────┬───────┐
│ id  │ orderId │ menuId │ price │
├─────┼─────────┼────────┼───────┤
│ i1  │ o1      │ m2     │ 6000  │  ← m2 참조 정상!
└─────┴─────────┴────────┴───────┘
```

**결과:**

```
POS 메뉴 화면 (isAvailable = true만 조회):

  ┌──────────────┐
  │ 아메리카노    │    ← 딸기스무디는 안 보임 (isAvailable = false)
  │   4,500원     │
  └──────────────┘


관리자가 주문 o1 상세를 조회하면:

  주문 #1
  ├─ 메뉴: 딸기스무디   ← m2 데이터가 살아있으니 정상 표시!
  ├─ 가격: 6,000원
  └─ 상태: 결제완료

  → 과거 이력 완벽 보존
```

---

## 비교 요약

```
Hard Delete (물리 삭제):

  [메뉴 삭제] → Menu 행 제거 → OrderItem이 참조하던 메뉴 소실
                                → 과거 주문 이력 깨짐 ❌


Soft Delete (isAvailable = false):

  [메뉴 비활성화] → Menu 행은 유지 (isAvailable = false)
                  → POS 화면에서는 안 보임 (쿼리에서 필터)
                  → OrderItem 참조 정상 유지
                  → 과거 주문 이력 보존 ✅
```

| 항목                         |     Hard Delete     |            Soft Delete             |
| ---------------------------- | :-----------------: | :--------------------------------: |
| 메뉴 화면에서 숨기기         |          O          |                 O                  |
| 과거 주문에서 메뉴 이름 조회 | **X** (데이터 없음) |               **O**                |
| DB 용량 절약                 |     O (행 삭제)     |            X (행 유지)             |
| 실수로 삭제 시 복구          |      **불가**       | `isAvailable = true`로 되돌리면 끝 |

결제 시스템에서는 **과거 이력 보존이 필수**이므로 soft delete를 선택한다.
